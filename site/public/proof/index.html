Smart Money Concepts on MT5 vs TradingView: the proof, object by object

LuxAlgo’s Pine script and this MQL5 port were run on the same 5,044 AAPL 15-minute bars. Everything each platform drew was exported and compared: 2,535 drawings and 20,176 candle colours, all identical. Below, you can look at both outputs yourself.

Loading the exports…
Same AAPL 15-minute bars, every feature on. The blink test flips between the two platforms twice a second, and nothing moves. Drag to scroll, double-click to reset.Drawn in your browser from the objects each platform exported.

Pick a configuration, switch between TradingView and MetaTrader 5, or press Blink test to flip between them. Differences fades every object that has an identical twin on the other platform and circles the rest. Scroll with the mouse wheel to zoom, drag to move in time, double-click to reset. Times are UTC. TradingView’s export does not record how far after the last bar a point lies; in this script those points (strong and weak highs and lows, daily, weekly and monthly levels) are always 20 bars ahead, as written in the Pine source, so that is where the viewer draws them.

The counts include the few objects that exist with no coordinates yet (Pine’s na), so they are a little higher than the number of objects drawn in the viewer.

The only gap comes from data, not code. On TradingView, weekly and monthly levels come from its own W and M bars (342.988), while MT5 rebuilds them from the chart’s bars (342.98, the true high of those bars). The anchors are identical. On a live MT5 account, W1 and MN1 come from the same feed as your chart. In the viewer, with config B and Differences on, these four weekly and monthly levels (PWH, PWL, PMH, PML) and their lines are the only objects circled, in amber.

Method

How the comparison was made

  1. Run the original. The unmodified Smart Money Concepts (SMC) [LuxAlgo] script ran on TradingView Desktop, AAPL 15 minutes. Pine runs on TradingView’s servers on their own set of bars (here 5,044), so that set was read first with a probe table.
  2. Export every drawing. Every label, line and box was read from the chart: time, price, text, text colour, style and size for labels; both ends, colour and style for lines; corners, fill, border and extension for boxes; plus the trend colour of every candle.
  3. Same bars in MetaTrader 5. The exact 5,044 bars were loaded into MT5 as a custom symbol, so both platforms worked on identical data.
  4. Run the port. SmartMoneyConcepts.mq5 ran with the same settings and dumped every object it drew.
  5. Compare as sets. Each object on one side must find an identical twin on the other side, field by field. Nothing is matched “approximately”.
  6. Real time. For configs A and B, the last 44 bars were replayed tick by tick (176 ticks), so the forming bar went through the port’s rollback logic, then compared again.

Configurations

  • A: the original defaults, with coloured candles on so that the trend of every bar is exported.
  • B: every feature on: swing points, swing order blocks, fair value gaps, daily, weekly and monthly levels, premium and discount zones.
  • C: the other branches of the code: Present mode, Monochrome style, confluence filter, cumulative mean range filter, Close mitigation, 20-bar swings, wider EQH/EQL threshold, fair value gaps on 30 minutes without auto threshold.
  • D: config C in Historical mode, which pushes Pine to its limit of 500 labels and checks that the port deletes the same oldest objects.

TradingView behaviours reproduced

  • Float tolerance. Pine compares numbers with an absolute tolerance of 1e-10: 0.1 + 0.2 == 0.3 is true, 1 + 0.9e-10 > 1 is false, 1 + 1e-10 > 1 is true, at any magnitude. Without it, one candle where the confluence filter compares 0.05 with 0.05 produced an extra CHoCH.
  • Points between bars. A point placed at a time with no bar (night, weekend) is drawn on the next bar.
  • Comparisons with na are false. No internal structure is drawn before the first swing exists.
